# streamreels

Локальный пайплайн: стрим-VOD (YouTube/Twitch) → вертикальные рилсы 9:16.

Что делает:
- качает источник (≤720p) и фоновый геймплей с YouTube;
- режет по твоим таймкодам;
- верхние ~60% — стрим с трекингом лица (плавный кроп-пан);
- нижние ~40% — зацикленный отвлекающий геймплей (subway surfers / parkour / GTA и т.п.);
- субтитры с word-level таймингами и подсветкой текущего слова (faster-whisper, локально, CPU).

Всё работает офлайн после первичной загрузки модели и клипов. GPU не нужен.

```bash
cd /home/dmitro/Projects/streamreels

```

Нужен `ffmpeg`/`ffprobe` в PATH (уже есть).

## Быстрый старт

```bash
# источник скачается сам; геймплей тоже (первый раз — дольше)
.venv/bin/python run.py "https://www.youtube.com/watch?v=XXXX" \
    -s 12:30-13:05 -s 45:10+30 \
    -o out

# локальный источник (если YouTube ботчекает — см. ниже)
.venv/bin/python run.py --local stream.mp4 --gameplay gameplay.mp4 \
    -s 1:00-1:40 -o out

# свой список запросов для фонового геймплея
.venv/bin/python run.py "<url>" -s 10-40 \
    --gameplay-query "minecraft parkour no commentary" \
    --gameplay-query "satisfying asmr"
```

Таймкоды: `start-end` (`12:30-13:05`, `1:02:03.5-1:02:33`) или `start+dur`
(`90+30`, `5.5+2`). `-s` можно повторять.

## Полезные опции

| Опция | Смысл |
|---|---|
| `-o DIR` | куда класть готовые рилсы (по умолчанию `out/`) |
| `--local FILE` | взять локальный файл как источник (без скачивания) |
| `--gameplay FILE` | локальный файл фона вместо автоскачивания |
| `--gameplay-query Q` | поисковый запрос для фона (можно несколько) |
| `--zoom 1.15` | зум кропа стрима (больше — ближе к лицу) |
| `--crf 20` | качество x264 (меньше — лучше/тяжелее) |
| `--preset veryfast` | скорость/качество x264 |
| `--no-subs` | без субтитров |


## Live-режим Twitch (реакция на звук + чат)

Бот смотрит живой стрим и режет рилс, когда в эфире происходит «хайп» —
**громкий момент** (смех, крик, взрыв эмоций), который подтверждается или
дублируется всплеском чата. Клип берётся **за несколько секунд до** момента и
рендерится как обычный VOD, только источник — кольцевой буфер.

```bash
.venv/bin/python run.py --live https://www.twitch.tv/<channel> --max-reels 1
```

Как это работает:

1. `yt-dlp -g` даёт HLS-плейлист потока; `ffmpeg` пишет его в короткие
   сегменты (кольцевой буфер, по умолчанию 120 с).
2. **Аудио-детект (основной сигнал):** у каждого финализированного сегмента
   считается RMS-громкость. Порог **адаптивный под канал**: хайп = энергия
   свежего сегмента выше `медиана + K·σ` фонового окна, где σ — робастная
   оценка разброса (MAD, устойчива к выбросам), `K = --audio-k` (по умолчанию
   3.0). Тихий стрим ловит скромный смех, шумный не срабатывает на фоне, а
   цифровая тишина не даёт ложных пиков. Дополнительно действуют ограничители:
   не ниже `--audio-ratio`× медианы и выше `audio_floor`. Громкость — самый
   точный сигнал: смех/крик слышно даже когда чат молчит.
3. **Чат (второй сигнал):** анонимный Twitch IRC (`#<channel>`) считает
   сообщения/сек. Каждое сообщение **взвешивается**: обычное = 1.0, за
   хайп-эмот (`KEKW`, `LUL`, `OMEGALUL`, `Pog`, `monkaS`, …) +0.5 за эмот
   (до +2), за смех (`хаха`, `lol`, `kek`, `xD`, `:D`) +1, за КАПС +0.5,
   итого не больше 4.0. Всплеск = **взвешенная** частота выше базовой в
   `--chat-threshold` раз. Так 10 `KEKW` весят как ~30 нейтральных сообщений —
   реакция на шутку важнее болтовни.
4. **Единый скор:** каждый сигнал даёт **непрерывную улику** — насколько он
   превышает свой порог (1.0 = ровно на триггере, 0 = фон, кэп 4.0). Они
   сливаются в один скор `--audio-weight·аудио + --chat-weight·чат`; клип
   режется, когда скор ≥ `--score-threshold`.
   Дефолты (`аудио 1.0`, `чат 0.4`, порог `0.7`) подобраны на размеченном банке
   из 18 клипов (5 каналов): **аудио почти идеально отделяет настоящий момент**
   (детекты, где доминировало аудио, — 100% попаданий), а **чат сам по себе
   шумный** (~33%): на мем-спам, бытовуху и болтовню он всплескивает так же, как
   на хайп. Поэтому чат **понижен**: он усиливает аудио и всё ещё срабатывает на
   по-настоящему взрывной чат (нужно `чат-улика ≥ порог / chat_weight`), но уже
   не тянет слабый клип в одиночку. Громкий смех режет клип сам, момент «оба
   тёплых» (аудио 0.6 + чат 0.5) тоже ловится.
5. На найденном моменте берётся окно `[момент − pre-roll, момент + post-roll]`
   из буфера (pre-roll нужен, чтобы захватить сам момент — детект срабатывает
   после).
6. **Пост-фильтр момента:** клип транскрибируется один раз (эти же слова идут
   в субтитры и описание — whisper не гоняется дважды) и проверяется, есть ли
   в нём живая речь. Отбрасываются моменты без речи (музыка/тишина) и те, где
   после пика сразу мёртвый воздух: нужно `--min-words-after` слов после пика
   и покрытие речью ≥ `--min-speech-ratio` от длины клипа. Дополнительно
   проверяется **качество транскрипта**: громкий шум/музыка заставляет whisper
   выдавать низкоуверенный многоязычный «мусор», который не смотрится.
   Клип отбрасывается как `garbled`, только если **одновременно** средняя
   уверенность слов < `--min-mean-conf` **и** доля слов с уверенностью <0.3
   выше `--max-low-conf-frac` (одно плохое условие терпим, чтобы не резать
   реальные шумные реакции). Оставшийся клип рендерится обычным пайплайном
   (субтитры → вебка-панель → 720x1280).

| Опция | По умолчанию | Смысл |
|---|---|---|
| `--live URL` | — | канал Twitch, который смотрим |
| `--pre-roll SEC` | `12` | сколько секунд до момента оставить |
| `--post-roll SEC` | `28` | сколько секунд после момента оставить |
| `--buffer-secs SEC` | `120` | длина кольцевого буфера |
| `--audio-k K` | `3.0` | адаптивно: хайп = громкость выше `медиана + K·σ` фона |
| `--audio-fixed` | выкл. | отключить адаптивный порог, считать по `--audio-ratio` |
| `--audio-ratio RATIO` | `1.6` | ограничитель (и режим `--audio-fixed`): выше медианы в N раз |
| `--no-audio` | выкл. | отключить аудио-детект, оставить только чат |
| `--chat-threshold RATIO` | `2.5` | всплеск = взвешенная частота выше базовой в N раз |
| `--audio-weight W` | `1.0` | вес аудио-улики в общем скоре |
| `--chat-weight W` | `0.4` | вес чат-улики (понижен: чат шумный сам по себе) |
| `--score-threshold S` | `0.7` | резать клип при скоре ≥ S (аудио на своём триггере = 1.0; чат-онли нужен `чат-улика ≥ S / chat_weight`) |
| `--max-reels N` | `0` | остановиться после N рилсов (0 — бесконечно) |
| `--no-moment-filter` | выкл. | не отбрасывать моменты без речи (музыка/тишина/мёртвый воздух) |
| `--min-words-after N` | `3` | пост-фильтр: минимум N слов после пика |
| `--min-speech-ratio R` | `0.03` | пост-фильтр: речь покрывает ≥ R длины клипа |
| `--min-mean-conf C` | `0.55` | пост-фильтр: отбрасывать «мусор» со средней уверенностью < C (только вместе со следующим) |
| `--max-low-conf-frac R` | `0.35` | пост-фильтр: …и доля слов с уверенностью <0.3 выше R |
| `--review-dir DIR` | — | сохранять каждый детект (принятый и отброшенный) с `index.csv` для разметки качества |

Особенности:

- Каждый запуск пишет в свой каталог `cache/live/<channel>/<run-id>/`, а
  процесс-рекордер привязан к родителю через `PR_SET_PDEATHSIG` — убитый
  прогон не оставляет «сиротский» ffmpeg, который портит буфер следующему.
- stderr рекордера пишется в `recorder.log` рядом с сегментами: если ffmpeg
  умрёт (протухший HLS-URL, обрыв сети), причина видна, а не теряется в
  `/dev/null`.
- Время клипа считается по **контентному** времени (сумма длительностей
  сегментов), а не по wall-clock — иначе джиттер скана режет клип не той длины.
  Аудио-пик сразу отдаёт контентное время, без маппинга wall-clock.
- Сеть нестабильна (TLS `BAD_RECORD_MAC`) — детект вебки идёт с ретраями.

## Метрика качества моментов (review-режим)

Чтобы тюнить детект не на глаз, а по цифре «сколько клипов реально попали в
момент»:

```bash
# 1. гоняем live с сохранением каждого детекта (и принятого, и отброшенного)
.venv/bin/python run.py --live https://www.twitch.tv/<channel> --review-dir review/ --max-reels 0

# 2. смотрим клипы и в review/index.csv ставим label = hit / miss (пусто — пропустить)
# 3. считаем точность, разброс по сигналам и рекомендуемый порог
.venv/bin/python tools/score_review.py review/ --precision 0.8
```

`--review-dir` кладёт рядом с каждым клипом `.txt` (score, аудио/чат-улики,
вердикт фильтра) и пишет `index.csv`. Сохраняются **и отброшенные** фильтром
моменты — так видно и промахи детекта, и ложные срабатывания фильтра.
`score_review.py` печатает текущую точность, медианы улик у hit vs miss (какой
сигнал лучше разделяет — тому и поднимать вес), свип `--score-threshold` и
**поиск весов**: он пересчитывает скор из сырых `audio_ev`/`chat_ev` и перебирает
`(audio_weight, chat_weight, threshold)`, выдавая лучшую комбинацию под заданную
точность — её строку копируешь в `--audio-weight/--chat-weight/--score-threshold`.
Так тюнинг становится замкнутой петлёй: разметил новый банк → прогнал → обновил
дефолты.

На первом банке (18 клипов, 5 каналов) вышло так: **аудио — честный сигнал**
(доминирование аудио = 100% попаданий), **чат-онли — почти монетка**: клипы с
`audio≈0` не разделяются по чату (`hit` при `chat 1.26` и `miss` при `chat 1.14`
различаются только шумом). Поэтому чат и понижен до веса 0.4 — он усилитель, а
не самостоятельный триггер.

## Описания и отправка в Telegram

По умолчанию субтитры включены, а к каждому готовому рилсу рядом кладётся
`.txt` с заголовком/описанием/хештегами (собираются из транскрипта рилса).

```bash
# отправить готовые рилсы в Telegram
.venv/bin/python run.py --live https://www.twitch.tv/<channel> --telegram --max-reels 1
.venv/bin/python run.py "<url>" -s 10-40 --telegram
```

- Бот: токен задаётся через `STREAMREELS_TG_TOKEN` (в репозитории не хранится).
- `chat_id` определяется из `getUpdates` (напиши боту любое сообщение один раз),
  либо задай `STREAMREELS_TG_CHAT_ID` / `--tg-chat ID`.
- Описание: эвристика по тексту. Хочешь «умные» описания от LLM — задай
  `STREAMREELS_LLM_API_KEY` (OpenAI-совместимый; опц. `STREAMREELS_LLM_URL`,
  `STREAMREELS_LLM_MODEL`), при ошибке автоматически откат на эвристику.
- Отправка идёт с ретраями (сеть тут флакает на TLS).

## Telegram-бот (приём ссылок)

Бот принимает ссылку и присылает готовые рилсы. Запуск:

```bash
.venv/bin/python run.py --bot
```

- Пришли боту ссылку на **Twitch-канал** (`twitch.tv/<name>`) → live-режим:
  смотрит стрим, ловит моменты, присылает по ходу (`STREAMREELS_BOT_LIVE_REELS`,
  по умолчанию 3 ролика).
- Ссылка на **VOD/clip/YouTube** → нарезка лучших моментов
  (`STREAMREELS_BOT_AUTO`, по умолчанию 3).
- Команды: `/status` (что в работе), `/stop` (прервать текущий live), `/help`.
- Вся тяжёлая работа идёт в **одном** воркер-потоке: одновременно крутится
  только один whisper (иначе машина уходит в OOM). Остальные запросы — в очереди.
- Доступ: задай `STREAMREELS_TG_ALLOWED=id1,id2` (или `STREAMREELS_TG_CHAT_ID`).
  Если ничего не задано, бот «привяжется» к первому чату, который ему напишет.
- Язык субтитров: `STREAMREELS_BOT_LANG` (по умолчанию `ru`).

## Заметки

- Первый запуск качает модель whisper (`large-v3-turbo`, ~1.6 ГБ, int8 ~1 ГБ в RAM).
  Для слабых машин: `WHISPER_MODEL=small` (~480 МБ) — быстрее, но заметно хуже на русском.
- Аудио декодируется через ffmpeg в numpy, поэтому не зависит от версии PyAV.
- Whisper-петли и фантомные фразы («субтитры сделал …») отключены/отфильтрованы.
- Вебка-панель детектится автоматически по каждому окну рилса (TypeSafe/jev),
  т.к. оверлей может переезжать по экрану. Фолбэк — статичная панель/`--webcam`.
- Сеть тут нестабильная: все загрузки идут с ретраями.
